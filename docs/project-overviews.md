# 项目商务概览与开发者署名

2026-10-10 对已上架游戏的 Project Overview 进行编辑。目标是让发行商和投资者快速了解产品定位与具体卖点：一条简短定位，加两至三条不重复的玩法、系统或内容特点。删除对玩家的购买呼吁、冗长剧情梗概和重复宣传语，保留有依据的独特机制；不添加销量、预算、愿望单数量、团队规模、投资回报或其他未经提供的信息。

英文、简体中文、韩文概览使用同样的事实和短段落、列表格式。开发阶段与合作需求已有独立模块，概览不重复这些资料。现有正文渲染器和审核后台的三语编辑功能仍可编辑这些 Markdown 文本。

优先核对已存在的 Steam 链接。没有链接时，先用官方搜索进行唯一的名称匹配，再核对产品内容；名称变体需要人工核对开发者、玩法或故事设定。Demo 与正式游戏分开识别，不能只凭相似标题随意关联。无法确定 Steam 页面时，只采用网站已有的开发者资料，不虚构来源。

网站的游戏开发者署名采用 Steam 英文页面的 `developers` 列表，保留全部署名与官方品牌拼写，不使用 `publishers` 代替开发者。Steam 只有中文署名时保留官方名称，不生成未经确认的英文公司名。游戏署名与网站账号所属公司是独立信息，编辑署名不转移游戏归属，也不修改账号、联系邮箱和工作室资料。

批量编辑先保留原三语正文、开发者署名和来源记录，生成草稿并核对要点与原文引用。正式写入前重新读取现有数据，使用旧值条件更新，避免覆盖工作期间被其他人编辑的内容。更新后检查所有字段，确保只有批准的三语正文和开发者署名发生变化。未上架申请不在此次内容编辑范围内。

封面仍采用 460:215 展示框；首页卡片、首页弹窗和账号中心游戏卡片改为居中铺满，对较高的旧封面上下裁切。

详情页采用方案 A：统一单栏。媒体、商务资料、开发进度、概览、工作室和联系模块共用页面容器的左右边界；桌面容器最大宽度 1080px（包括左右各 30px 留白）。媒体保持 16:9，概览使用全宽面板，面板内正文维持最多 72ch 的阅读行宽。工作室介绍同样限制行宽，较长的官方开发者名称可以换行。

缩略图保持单行，超出部分在条带内部横向滚动；手机可左右滑动，键盘 Tab 聚焦后可用 Enter 或空格选择图片。缩略图按钮提供三语名称、选中状态和可见的焦点样式。手机顶部导航分两行显示，防止语言切换和账号入口挤出屏幕。没有概览、工作室或进度资料时不显示空模块。

本地静态服务启动在 8811 端口后，可运行 `NODE_PATH=/workspace/.setup-tools/node_modules node tests/detail-layout.cjs`。该检查覆盖八种屏幕宽度与三语模块边界、正文行宽、媒体比例、单行缩略图、键盘选择以及可选模块。
